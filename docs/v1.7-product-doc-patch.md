## 10. v1.7 跨画布引用 + 总控画布模式

### 10.1 是什么
PlotMesh v1.7 引入"跨画布引用 (Cross-Canvas Reference)"机制，允许多个画布之间用**1 对 1 关联**互相投递数据，构成"总控画布 + 子画布"的协作模式。

新增两个节点：
- **🌐 crossOutput**（跨画布输出）：把上游内容投递到另一个画布的 crossInput
- **🌐 crossInput**（跨画布输入）：接收远端 crossOutput 的回写；source 由 server 自动填，readonly（不能手改"来自哪里"）

### 10.2 适用场景
- **项目管理**：一个总画布派任务到多个子画布；子画布跑完结果自动汇总回总画布
- **子系统隔离调试**：某个子流程在独立画布上验证完整再接到主画布，主画布不用每次重跑整条链
- **状态监控**：总画布看到 crossInput 节点的 status (waiting / received) 就知道哪个子任务在跑/堵了
- **避免巨型画布**：单画布啥都做体感能用，但子系统不能并行验证；多画布协调把这个问题解决了

### 10.3 "我在等结果"开关（核心交互）
**这是 P2-A 的精髓**：

- **同画布内** crossOutput → crossInput **有连线** = "我在等结果，远端跑完自动继续我这边"
  - server 检测到这条边 → crossOutput 投出去后**自动 cascade 触发**远端画布运行
  - 远端跑完 → crossOutput 写到本画布 crossInput → 本画布继续跑下游
- **没连线** = "我只是把数据丢出去，你那边什么时候跑、跑不跑我不管"
  - 适合调试 / 手动闭环 / 架构里的"开关"

类比：连了线就是"我在等你电话"，没连就是"我把任务给你，你自己决定何时做"。

### 10.4 配置流程
1. **A 画布上加 `crossOutput` 节点** → 双击或点节点上的"配置目标画布 →"
2. 弹窗选目标画布 B；选择"在 B 上自动建一个 crossInput"（默认）或"接收 B 上已有的某个未关联 crossInput"
3. 确认 → server 自动建立 1 对 1 关联（写入 connections 表）
4. 在 A 上把上游节点连到 crossOutput；如果想"远端跑完自动继续 A"，再把 crossOutput 连到 A 内的某个 crossInput（"我在等"开关）
5. B 画布上对应的 crossInput 自动出现（位置在画布右侧空白处），有 readonly 标签 `🌐 ← 来自画布 A / output-X`
6. 在 B 上把 crossInput 连到下游处理节点；最后用 B 的 crossOutput 回送结果到 A.crossInput

### 10.5 多对多怎么实现
跨画布层面只有 1 对 1。一对多 / 多对一靠在画布内连边实现：
- 一对多：A.crossOutput 数据 → A 画布内连到多个下游，或者建多个 crossOutput 投到不同画布
- 多对一：B 画布内多个上游连到同一个 crossOutput / B 上多个 crossInput 都连到同一个汇总节点

跨画布"多源汇入"的拼接策略由用户在画布内自己决定（用 textTransform 拼接 / 用 condition 选源等）。

### 10.6 循环检测
crossOutput → crossInput → crossOutput → ... 形成环时，server 用 traceId + traceDepth 防无限循环：
- 每条 cascade 链最多 10 层深度
- 超过自动停止，记录到日志

### 10.7 解除关联
- 在 crossInput 节点上点"解除关联"按钮
- 或调用 `DELETE /api/canvas/connections/:connId`
- 解除后双向清空 src/dst 节点上的链接信息，但节点本身保留

### 10.8 server 端 API（外部 AI 也能用）
- `GET /api/canvas/connections?canvasId=` 列出某画布相关的所有关联
- `POST /api/canvas/connections` body `{srcCanvasId, srcNodeId, dstCanvasId, dstNodeId?}` 建立关联
- `DELETE /api/canvas/connections/:connId` 解除关联
- `GET /api/canvas/connections/by-src?canvasId=&nodeId=` 查 src 节点关联
- `GET /api/canvas/connections/by-dst?canvasId=&nodeId=` 查 dst 节点关联

### 10.9 双引擎执行（v1.7 P1）
- **前端 ▶️ 按钮**：跑前端引擎，零延迟，适合阶段性小验证
- **外部 AI / curl / 定时触发**：走 server runner，runs 持久化到 `~/.plotmesh/runs/<jobId>.json` LRU 100 条
- 跨画布 cascade 只在 server runner 触发；前端 ▶️ 跑到 crossOutput 时也会走 server 处理跨画布投递（确保多画布协调一致）

## 11. server 启动方式（v1.7 起）

| 方式 | 命令 | 适合 |
|---|---|---|
| 手动前台 | `cd server && npm start` | dev 调试 |
| 手动后台 | `cd server && nohup npm start > /tmp/plotmesh-server.log 2>&1 &` | 不占终端 |
| **开机自启** ⭐ | `bash scripts/install-autostart.sh` | 一劳永逸（launchd 自动起 + 崩溃自动拉起） |
| 自启状态 | `bash scripts/install-autostart.sh --status` | |
| 自启卸载 | `bash scripts/install-autostart.sh --uninstall` | |
| Docker 部署 | `bash scripts/deploy-to-nas.sh` | 群晖 / QNAP NAS 团队部署 |
